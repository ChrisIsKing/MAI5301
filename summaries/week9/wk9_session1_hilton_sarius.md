Flash-Decoding for long-context inference

The Flash-Decoding approach fixes a major performance problem in modern large language model (LLM) inference: the high cost of attention during decoding, especially for very long contexts. When LLMs use autoregressive generation, they produce text one token at a time, and each new token must pay attention to all the tokens that came before it. Key/value caching helps save the transformer forward pass from having to be recomputed too often, however the attention computation still doesn't work well with long contexts. As LLMs have gotten better at handling very large input sequences, such 32 K tokens in LLaMA-2-32K and even 100 K in CodeLlama, attention has started to take over inference time and cost. This is especially a problem when batch sizes are tiny, which is usually the case in real-time generating apps. In these cases, traditional FlashAttention and other kernels don't fully exploit GPU computation resources, which causes excessive latency and inefficient hardware consumption. Because of these performance issues, long-context LLMs are hard to use on a large scale and aren't very useful in real-world systems.

Related research in this domain has concentrated on enhancing attention execution, especially via memory-efficient algorithms like FlashAttention. FlashAttention speeds up traditional attention by reducing memory traffic across GPU tiers. This makes training and inference faster than naive implementations.However, it is primarily optimized for training workloads, where parallelism can be exploited across both batch and sequence dimensions. During decoding at inference time where query length is typically one and attention must stream over the entire accumulated history FlashAttention underutilizes GPU resources, because only a small fraction of the hardware is engaged when batch sizes are small. Other systems, such as FasterTransformer, also offer custom kernels, but they have the same problems when sequence lengths get too long. So, it was evident that there was a need for a decode-time optimisation that was made only for the way inference works.

To fix this, Flash-Decoding builds on the FlashAttention model by adding a new way to parallelise over the length of the key/value sequence. The main idea is that you can calculate attention in decoding over splits of the stored key/value tensors over and over again. Flash-Decoding works in three steps: (1) it breaks up the long list of keys and values into smaller pieces; (2) it uses FlashAttention to calculate the attention of the current query to each piece at the same time, while also collecting a log-sum-exp scalar per piece to summarise partial scores; and (3) it uses those scalars to combine partial results into the right full attention output in an efficient way. This way gets rid of the serial memory bottleneck that happens when you read huge key/value caches in chunks with current approaches. By taking use of this extra parallelism, Flash-Decoding can keep the GPU busy even when the batch size is 1 and the contexts are long. This means that it can generate sequences up to 8 times quicker than other methods like PyTorch primitives, FlashAttention v2, and FasterTransformer.

One problem with the Flash-Decoding method is that its speed gains rely on the length of the sequence. For shorter contexts, the extra work of splitting and reducing may not be worth the benefits of more parallelism. Also, Flash-Decoding greatly increases the throughput of attention, but it doesn't fix other possible bottlenecks in the complete inference pipeline, including feedforward calculations or KV cache memory footprints. It also assumes that GPU architectures can handle the requisite parallel kernels well. Performance on specialised hardware, like TPUs or low-power inference accelerators, may not see the same improvements.

Future research areas encompass the integration of Flash-Decoding with additional advances to further diminish inference delay and resource expenditures. Possible ways to improve the algorithm include adaptive splitting strategies that choose the best chunk sizes based on the model architecture and hardware characteristics; integration with speculative decoding or early exit techniques to lower the total compute per token; and extending the algorithm to better use heterogeneous hardware (for example, CPU-GPU co-scheduling). Researchers may also integrate Flash-Decoding with memory optimisation strategies to provide extended contexts without corresponding memory expansion.


Efficient Memory Management for Large Language Model Serving with PagedAttention

In the last several years, big language models (LLMs) have become quite popular in many different types of applications, such as chatbots, summarisation, and answering questions. But efficiently serving these models on a large scale is still a big engineering problem. A major issue is how the transformer architecture deals with autoregressive decoding. In this process, each new token has to pay attention to all the tokens that have already been issued and keep a growing key-value (KV) cache. Because inference workloads have a lot of requests at the same time, the KV cache memory for each request grows and often has a lot of memory that isn't being used because it is fragmented or duplicated. This inefficiency limits the number of requests that may be grouped together, which slows down throughput and raises the cost of hardware for systems that serve real-time data. It is very important to fix this problem because throughput and latency have a direct impact on the user experience and the cost of running LLM services in production.

FasterTransformer and Orca are two examples of older systems for LLM serving. They use standard attention algorithms and KV cache methods that see cache memory as continuous arrays. These systems work rather well, but in practice, they waste memory since they have to reserve enormous blocks of memory ahead of time, and they can't easily reclaim or share parts that aren't being used. Also, as request sequences might be different lengths, the difference between logical and physical memory causes internal fragmentation, duplication across simultaneous requests, and small batch sizes. Many studies have tried to make attention computation better (for example, FlashAttention for memory-efficient execution), but memory management is still a problem for scale inference.

To solve this problem, the authors suggest PagedAttention, a new attention algorithm based on how operating systems use virtual memory and paging. In PagedAttention, the KV cache of a request is split into blocks of a certain size (like memory pages) that can be stored in physical memory that isn't next to each other. There is a mapping between logical blocks (the sequence's view) and physical memory. This lets memory grow dynamically as tokens are made, without having to set aside vast, contiguous slabs in advance. This structure lets the system put KV blocks wherever in GPU RAM and, when needed, reclaim or distribute blocks between requests. The authors create vLLM, a serving engine that uses almost less memory and lets KV caches share data in a flexible way. It is built on top of PagedAttention. In tests, vLLM increases the throughput of common LLMs by 2 to 4 times compared to the best available at the same latency. The improvements are particularly noticeable for longer sequences and bigger models.

One important thing that led to this method is realising that attention computation doesn't need contiguous KV memory; it just has to go through all the previous keys and values. PagedAttention maintains accuracy while allowing for much more efficient memory use by using a paged memory layout and smart block mapping. This is comparable to how virtual memory enables operating systems interpret a process's address space as one big block, even when its pages are spread out in physical memory.

The proposal has some good points, but it also has some bad ones. First, handling block tables and doing indirect memory lookups can make the kernel more complicated, which can lead to small inefficiencies in single-sequence decoding when memory isn't the problem. Second, even though vLLM cuts down on memory waste by a lot, it still needs careful tuning of block sizes and mapping strategies to find the right balance between throughput and memory overhead. Lastly, the method is made for GPU environments and may not work as well on other hardware, like TPUs or bespoke accelerators, without some changes.

Future study could investigate adaptive block sizing that dynamically adjusts page granularity according to workload parameters, or hybrid solutions that integrate paged attention with the compression of KV states to further minimise memory usage. Integration with dispersed serving environments and different types of hardware could possibly make it possible to get even more throughput at scale. Overall, PagedAttention is a big step toward LLM serving systems that are more efficient and cost-effective.
