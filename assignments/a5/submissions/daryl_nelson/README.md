## Why Classification Fine-tuning Differs from Pretraining

Pretraining GPT‑2 is an unsupervised next‑token prediction task over a huge, diverse text corpus, where the model learns general language patterns without explicit labels. In this assignment, we repurpose that pretrained model for a supervised binary classification task (ham vs spam). Instead of predicting the next token over a 50,257‑word vocabulary, we replace the language modeling head with a small classification head that outputs logits for two classes and train it using cross‑entropy on labeled SMS messages. We also only use the final token representation for each message as the summary of the sequence, because causal self‑attention ensures this token has aggregated information from all previous positions. As a result, gradients are guided by discrete class labels rather than by language modeling loss, and optimization focuses on decision boundaries between ham and spam instead of general text continuation.

## Impact of Freezing Strategies on Performance

The notebook compares two fine‑tuning strategies: partial freezing and full fine‑tuning. In the partial freeze setup, almost all GPT‑2 parameters are frozen and only the last transformer block, the final layer normalization, and the new classification head (about 8M parameters) are updated. This dramatically reduces the number of trainable weights and thus training time and memory usage, while still allowing the model to adapt higher‑level representations to the spam task. In the full fine‑tuning setup, all ~124M parameters are updated with a smaller learning rate to avoid catastrophic forgetting. The notebook evaluates both strategies using accuracy, precision, recall, and F1 scores on a held‑out test set. Partial freezing is expected to converge faster and be less prone to overfitting on small datasets due to the regularizing effect of frozen weights. Full fine‑tuning offers more flexibility to reshape internal representations but brings higher computational cost.

## Dataset Characteristics and Challenges

We use the SMS Spam Collection dataset from the UCI repository, which contains short text messages labeled as "ham" (legitimate) or "spam" (unsolicited). The raw dataset is highly imbalanced (around 87% ham and 13% spam), which can bias models toward predicting the majority class. To mitigate this, the notebook constructs a balanced subset by undersampling ham messages so that ham and spam counts match. The balanced data is shuffled and split into 70% training, 10% validation, and 20% test. Messages are tokenized with GPT‑2's BPE tokenizer (tiktoken), then truncated or padded to a fixed length using the end‑of‑text token. Key challenges include the small absolute number of spam examples, high lexical variation (informal language, abbreviations, and noisy spelling), and the risk that aggressive truncation might remove discriminative cues from longer messages.

## Model Strengths and Weaknesses

**Strengths.** Leveraging GPT‑2's pretrained weights gives the classifier a strong prior over natural language, which should help it generalize from the relatively small spam dataset. The partial freeze variant is particularly attractive in resource‑constrained settings: it retains most of the pretrained knowledge and requires updating only a small fraction of parameters. The notebook generates confusion matrices, classification reports, and training curves to assess both strategies.

**Weaknesses.** Because the dataset is small and domain‑specific, the model can still overfit, especially under full fine‑tuning where all layers are updated. Some spam messages that resemble normal conversational text or use less typical spam patterns remain difficult, leading to false negatives. Conversely, very enthusiastic or promotional but legitimate messages can be misclassified as spam (false positives). The model also inherits biases from GPT‑2's pretraining corpus and is limited by the fixed input length; any important cues beyond the truncation limit are lost. Finally, generalization to other spam domains (e.g., email, social media, different languages) would likely require further domain‑specific fine‑tuning.
